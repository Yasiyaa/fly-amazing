## Checked and sound
- **RLS:** turned on for all 13 tables. Anon and non-staff users can't touch bookings, enquiries, chats or staff. Catalogue, settings and media writes need `is_staff()`, which is security definer with `search_path` set. `reserve_chat_turn` and `record_chat_tokens` can only be run by `service_role`. Storage: staff-only writes, no anon listing, 50 MB limit, no SVG/HTML.
- **Service-role paths:** rows are built field by field (no mass assignment) and prices are calculated on the server. The lookup needs reference + email, returns the same 404 either way, has 31⁵ possible references and is rate-limited.
- **Admin:** every action calls `requireStaff()` (checked with `getUser()`). Next checks Origin on server actions. No open redirects.
- **Output:** no `dangerouslySetInnerHTML`. Email values are escaped with `esc()`. WhatsApp and tel links keep digits only. Planner tools are read-only.
- **Secrets:** none in history. Only the Supabase URL and anon key reach the client. The cron route rejects requests without `CRON_SECRET`.
